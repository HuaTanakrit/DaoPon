# DaoPon frontend

การ deploy ทั้งสองแอปใน Vercel project เดียวอยู่ที่ [คู่มือ Vercel](../docs/DEPLOY_VERCEL.md) Service binding ฉีด BACKEND_URL ภายในให้อัตโนมัติ ส่วน auth/prediction routes ยังคงผ่าน Next.js

## ควบคุมเวลาเดโม

เปิด `/demo` หรือกด “ปรับเวลาเดโม” ในแถบด้านบน เลือกเวลาไทยในฤดูกาล 2024/25 ได้เอง หรือเลือกหนึ่งใน 380 แมตช์แล้วกดก่อนแข่ง 1 วัน → เวลาเริ่มแข่ง → หลังเริ่มแข่ง 3 ชม. เพื่อโชว์ลำดับการทายและตรวจคะแนน มีลิงก์เปิดหน้าทายของแมตช์ที่เลือกและปุ่มกลับเวลาปกติ เวลาเดโมหยุดค้างและใช้ร่วมกันทั้งเว็บ แถบด้านบนตรวจการเปลี่ยนเวลาในแท็บอื่นทุก 5 วินาที

ต้องเปิด `DEMO_CONTROLS_ENABLED=true` และกำหนด `DEMO_CONTROL_TOKEN` เหมือน backend ใน `.env.local` ทั้งสองค่าเป็น server-only ไม่ใช้ `NEXT_PUBLIC_` บน Vercel เพิ่ม `DEMO_ADMIN_EMAILS` และ Login ด้วยบัญชีที่อนุญาตก่อนใช้ตัวควบคุม ผลตรวจต้องรอ API ยืนยันข้อมูลจริง คะแนนที่ตรวจแล้วไม่ถูกล้างเมื่อย้อนเวลา

## บัญชีและคะแนน

- `/register` สมัครด้วยชื่อ อีเมล และรหัสผ่าน
- `/login` เข้าสู่ระบบและกลับไปหน้าสร้างทีมเดิมผ่าน `next`
- `/account` ดูคำทำนายทั้งหมด คะแนนแยกสโมสร และรายชื่อที่ทายถูกต่อแมตช์

การสร้าง/บันทึกทีมต้องเข้าสู่ระบบ ทีมและคะแนนผูกกับบัญชี เปิดจากเครื่องอื่นได้ ไม่ใช้ guest cookie เป็นตัวตนหลักแล้ว เมื่อสมัคร/เข้าสู่ระบบในเบราว์เซอร์เก่าจะนำคำทำนาย guest ที่ยังไม่ถูกผูกไปเข้าบัญชีให้ หากบัญชีมีของแมตช์นั้นแล้วจะใช้ข้อมูลของบัญชี

หน้า account รีเฟรชคะแนนทุกนาที ทายถูก 1 คน = 1 คะแนน ไม่เทียบตำแหน่ง คะแนนของ Liverpool และ Manchester United แยกกัน สถานะรอเฉลยคงอยู่จน backend รับ startXI ครบหลังเวลาในเกมเริ่มแข่ง 3 ชั่วโมง ไม่แสดงเป็น 0 คะแนนก่อนตรวจผล

หน้า `/fixtures/[id]/predict?team=40` มีฟอร์มทายสกอร์เจ้าบ้าน/ทีมเยือน บันทึกแยกจากตัวจริงและทายสกอร์อย่างเดียวได้ รับจำนวนประตู 0–99 เปิด 7 วันก่อนแข่งและปิดเมื่อ kickoff สกอร์ตรงได้ 3 คะแนน ผลชนะ/เสมอ/แพ้ถูกแต่สกอร์ไม่ตรงได้ 1 คะแนน ผิดได้ 0 คะแนน รวมสูงสุด 3 คะแนนต่อนัดต่อสโมสร หน้า `/account` แยกยอดและประวัติทายสกอร์จากคะแนนตัวจริง พร้อมสถานะรอเฉลยจน API ยืนยันผลหลัง kickoff ในเกม 3 ชั่วโมง

Cookie session เป็น HttpOnly อายุ 30 วัน การสื่อสารกับ backend และ token อยู่เฉพาะ Route Handlers ฝั่ง server คำขอเปลี่ยนข้อมูลต้องผ่านการตรวจ Origin/Host ทุกครั้ง

Next.js 16 + React 19 + TypeScript อยู่ในโฟลเดอร์ frontend ของ Premier

## รันบนเครื่อง

ให้ backend ทำงานที่ http://localhost:3001 ก่อน แล้วรันจากโฟลเดอร์ frontend:

```sh
npm install
npm run dev
```

เปิด http://localhost:3000

`BACKEND_URL` ใน `.env.local` เป็น URL ฝั่ง server ของ Next.js ไม่ต้องใส่ API key, admin token หรือ DATABASE_URL ใน frontend

## หน้าที่มี

- `/` เลือก 20 สโมสรพรีเมียร์ลีกของฤดูกาล 2024/25 และค้นหาด้วยชื่อไทย อังกฤษ หรือชื่อย่อ
- `/teams/[id]` รายชื่อนักเตะ ค้นหาชื่อ กรองตำแหน่ง และเรียงตามชื่อ ประตู หรือแอสซิสต์
- `/fixtures` ตารางแข่งขันที่ยังไม่เริ่มในเวลาจำลองย้อนหลัง 2 ปี กรองสโมสรและโหลดเพิ่มได้ วันเวลาเป็น Asia/Bangkok โดยแสดงปี ค.ศ.
- มี loading, error พร้อมปุ่ม retry และหน้า 404
- ปรับ layout สำหรับมือถือและรองรับ keyboard focus

ข้อมูลมาจาก NestJS → Neon PostgreSQL การเปิดหน้าเว็บและค้นหาในหน้าไม่เรียก API-Football โดยตรง

หน้าตารางใช้เวลาจำลองจาก backend เช่น 29/10/2026 → 29/10/2024 และไม่รับสกอร์หรือตัวจริงจาก API ตาราง รายการจะหายเมื่อถึงเวลาเริ่ม พร้อม refresh ข้อมูลจาก server ทุกนาที

หน้านักเตะใช้ `/api/players/replay` และรวมเฉพาะสถิติรายนัดที่เริ่มมาอย่างน้อย 3 ชั่วโมงถึงวันจำลอง แสดงวันตัดยอดและความครบ เช่น `9/9 นัด` ถ้ายังดึงไม่ครบจะแสดงหมายเหตุและเฉพาะยอดจากแมตช์ที่นำเข้าแล้ว รายชื่อเป็นผู้เล่นที่มีชื่อใน match sheet ถึงวันนั้น ไม่รวมผู้เล่นที่เพิ่งมีข้อมูลในอนาคต ตัวสำรองที่ไม่ได้ลงสนามไม่ถูกนับเป็นการลงเล่น หน้าเว็บ refresh ข้อมูลทุกนาที

เติมสถิติด้วย `npm run data:replay-stats` จาก root ของ Premier โดย cache อยู่ใน `backend/.cache/football/2024/matches` worker backend ที่เปิดด้วย `REPLAY_STATS_SYNC_ENABLED=true` จะเติมต่อทุกชั่วโมงนาที 05 เมื่อมีโควตา

เตรียมตาราง 380 นัดด้วย `npm run data:fixtures` จาก root ของ Premier หรือ backend โดยเก็บ cache ใน `backend/.cache/football/2024/fixtures.json`

## ข้อมูลเริ่มต้น

นำข้อมูลจาก API-Football เข้าฐานข้อมูลแล้ว 20 สโมสร นักเตะ 1,055 คน และ season snapshots 1,132 แถว จำนวน snapshots มากกว่าจำนวนนักเตะได้เมื่อมีการย้ายสโมสร

ข้อมูลนี้เป็นฤดูกาล **2024/25** ตามสิทธิ์บัญชี Free ไม่ใช่รายชื่อปัจจุบันของฤดูกาล 2026/27

บัญชี Free จำกัด `page` สูงสุด 3 จึงดึงแยกสโมสร และยังมีรายชื่อไม่ครบใน 6 สโมสร ได้แก่ Manchester United, Newcastle, Chelsea, Manchester City, Brighton และ Aston Villa หน้าสโมสรเหล่านี้แสดงหมายเหตุจาก coverage ที่บันทึกในฐานข้อมูล

สคริปต์ `npm run data:seed` จาก root จะอ่าน public response cache ใน `backend/.cache/football/2024` และ upsert ฐานข้อมูล หากต้อง fetch ใหม่จะใช้โควตา API จึงไม่ควรลบ cache แล้วรันซ้ำโดยไม่จำเป็น API key ยังคงอยู่เฉพาะ `backend/.env`
